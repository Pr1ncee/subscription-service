# ТЕСТОВОЕ ЗАДАНИЕ

## Описание задачи
Вам необходимо разработать серверную часть приложения для обработки платежей по
пользовательским подпискам и рассылки уведомлений о них. По возможности используйте технологии из списка - FastAPI, FastStream, asyncio, PostgreSQL, RabbitMQ

Приложение должно предоставлять следующие возможности:

1. Создать/обновить подписку пользователя и запланировать отправку уведомления по ней.
Пример входных данных: `user_id` (str), `subscription_id` (str),  `day_count` (int), `expected_expires_on` (datetime).
2. Получить текущее состояние подписки и историю запланированных/отправленных по ней
уведомлений.
Пример входных данных: `subscription_id`, `user_id`, `expected_expires_on`, `day_count`,
список уведомлений (`event_name`, `scheduled_for`, `sent_at | null`, `status`).
3. Зафиксировать платёж по подписке и поставить в очередь событие о его результате
(например, для отправки пользователю уведомления об успешной/неуспешной оплате или для продления
подписки).
Пример входных данных: `subscription_id` (str), `provider_payment` (str), `amount` (decimal),
`currency` (str), `status` (`"succeeded" | "failed"`).
Поведение: запись платежа и событие о нём должны либо оба зафиксироваться, либо ни одно —
"платёж записан, но уведомление/событие о нём потеряно" — недопустимый результат работы сервиса.
4. Получить статус платежа и факт того, было ли по нему отправлено событие/нотификация
(для диагностики/проверки гарантии доставки).

Самостоятельно проработайте функциональные и нефункциональные требования и реализуйте настолько глубоко насколько посчитаете нужным - жестких рамок нет. Предлагаемое решение просим предоставить в формате git-репозитория. Не воспрещается использование AI-агентов, если они будут использованы - будет плюсом оставить артефакты от этапов анализа, проектирования, и инструменты для работы с агентом - например правила (скилы) и тому подобное.
